PROBLEMA RESOLVIDO: FILE_PATH HARDCODED
================================================================================

QUAL ERA O PROBLEMA:

No arquivo `lib/dropboxClient.js`, a linha 19 estava assim:
  const FILE_PATH = '/ClubeDoCinema.xlsx';

Isso causava:
  - Localhost: usava ClubeDoCinema.xlsx (ERRADO - deveria usar DEV)
  - Vercel: usava ClubeDoCinema.xlsx (correto para produção)

RAIZ DO PROBLEMA:
  - A variável DROPBOX_FILE_NAME não estava sendo usada
  - O arquivo tinha o nome hardcoded (escrito na mão)
  - Impossível distinguir localhost de Vercel

SOLUÇÃO IMPLEMENTADA:

Mudamos para:
  const FILE_PATH = `/${process.env.DROPBOX_FILE_NAME || 'ClubeDoCinema.xlsx'}`;

Agora:
  ✅ LOCALHOST:
     - Arquivo `.env.local` tem: DROPBOX_FILE_NAME=ClubeDoCinema_DEV.xlsx
     - Resultado: usa ClubeDoCinema_DEV.xlsx (desenvolvimento)

  ✅ VERCEL:
     - Sem variável configurada no Dashboard
     - Usa fallback do código: ClubeDoCinema.xlsx (produção)
     - Resultado: usa ClubeDoCinema.xlsx (produção segura)

COMO FUNCIONA:
  1. O código tenta ler `process.env.DROPBOX_FILE_NAME`
  2. Se existir (localhost tem em .env.local): usa ela
  3. Se não existir (Vercel sem configuração): usa fallback

NUNCA será usado ClubeDoCinema_DEV.xlsx no Vercel!

Explicação:

  - Precisa reiniciar npm run dev para ler as mudanças

Quando usar:
  - Toda vez que quer testar mudanças localmente

SEÇÃO 6: COMANDOS GIT - VISUALIZAR HISTÓRICO
================================================================================

Comando:
  git log --oneline -5

Explicação:
  - "git log" = mostrar histórico de commits
  - "--oneline" = formato compacto (uma linha por commit)
  - "-5" = mostrar apenas os últimos 5 commits

O que mostra:
  Exemplo:
    a22284c Corrigir FILE_PATH para usar DROPBOX_FILE_NAME
    7a13fe3 Adicionar DROPBOX_FILE_NAME para usar planilha DEV
    b94c4a2 Sincronizar arquivo Ver filmes/avaliar em funcionamento
    9bf76ef Force rebuild
    39f7ccd Força rebuild no Vercel

Quando usar:
  - Quer ver quais mudanças foram feitas
  - Quer encontrar um commit específico para reverter
  - Quer verificar o histórico antes de fazer revert

================================================================================
SEÇÃO 7: COMANDOS GIT - GUARDAR MUDANÇAS TEMPORÁRIAS
================================================================================

Comando:
  git stash

Explicação:
  - "stash" = guardar/armazenar mudanças temporariamente

O que faz:
  - Salva todas as mudanças locais em um "cofre"
  - Limpa a pasta (como se nada tivesse sido editado)
  - Útil quando há conflitos ou precisa mudar de branch

Situações de uso:
  - Tem mudanças não commitadas que conflitam com um revert
  - Precisa mudar de branch mas tem alterações pendentes
  - Quer descartar tudo e começar de novo

Recuperar depois:
  git stash pop  (tira do cofre e coloca de volta)

================================================================================
SEÇÃO 8: COMANDOS GIT - DESFAZER UM COMMIT
================================================================================

Comando:
  git revert 7a13fe3 --no-edit

Explicação:
  - "revert" = reverter/desfazer um commit anterior
  - "7a13fe3" = código do commit (vê com git log --oneline)
  - "--no-edit" = não abre editor, usa mensagem automática

O que faz:
  - Cria um NOVO commit que desfaz as mudanças do commit antigo
  - O histórico fica intacto (não apaga nada)
  - Seguro, rastreável, não destrutivo

Quando usar:
  - Fiz um commit errado que foi para Vercel
  - Descobri um bug depois de fazer push
  - Preciso desfazer sem apagar o histórico

Passo a passo:
  1. git log --oneline (encontra o commit errado)
  2. git revert abc1234 --no-edit (desfaz)
  3. git push (envia o revert para GitHub e Vercel)

Resultado:
  - Novo commit aparece: "Revert 'mensagem do commit antigo'"
  - As mudanças do commit antigo são DESFEITAS
  - Vercel detecta e faz deploy com as mudanças desfeitas

================================================================================
SEÇÃO 9: COMANDOS GIT - PREPARAR ARQUIVOS
================================================================================

Comando:
  git add .

Explicação:
  - "git add" = adicionar/preparar arquivos para commit
  - "." = TODOS os arquivos que foram modificados

O que faz:
  - Marca todos os arquivos alterados para serem salvos
  - Sem git add, as mudanças não são incluídas no commit
  - É o passo ANTES de git commit

Fluxo correto:
  1. Editar arquivos (feito)
  2. git add . (preparar)
  3. git commit -m "mensagem" (salvar)
  4. git push (enviar)

Dica:
  Sempre faça "git status" antes de git add para ver o que vai entrar.

================================================================================
SEÇÃO 10: COMANDOS GIT - SALVAR MUDANÇAS (COMMIT)
================================================================================

Comando:
  git commit -m "Descrição clara e concisa"

Explicação:
  - "git commit" = salvar mudanças permanentemente
  - "-m" = adicionar mensagem
  - Tudo entre aspas é a mensagem do commit

O que faz:
  - Cria um "ponto de salvação" no histórico do Git
  - Todos os arquivos do git add são incluídos
  - Você cria um registro do que foi mudado e por quê

Boa mensagem de commit:
  git commit -m "Corrigir FILE_PATH para usar DROPBOX_FILE_NAME"
  (Descreve O QUÊ foi feito, de forma clara)

Exemplo RUIM:
  git commit -m "mudou coisa"
  (Não explica nada)

Dica:
  Use verbos no infinitivo (Corrigir, Adicionar, Atualizar, Remover)
  Seja específico (o quê foi feito)

================================================================================
SEÇÃO 11: COMANDOS GIT - ENVIAR PARA GITHUB
================================================================================

Comando:
  git push

Explicação:
  - "push" = empurrar/enviar commits para GitHub

O que faz:
  - Envia seus commits locais para o repositório remoto (GitHub)
  - Se você estiver em "main": Vercel detecta e faz deploy automático
  - Se estiver em "development": nada acontece (seguro)

IMPORTANTE:
  - NUNCA faça git push sem testar no localhost primeiro
  - Sempre teste antes de push para main
  - Use development para experimentar sem medo

Processo completo:
  1. Fez mudanças no código
  2. git add .
  3. git commit -m "mensagem"
  4. npm run dev (testa no localhost)
  5. git checkout main (volta para main)
  6. git merge development (traz mudanças)
  7. git push (envia para GitHub - DISPARA VERCEL!)

O que acontece depois:
  - GitHub recebe seu código
  - Vercel detecta o push na branch main
  - Vercel inicia o build/deployment
  - Em 1-3 minutos, o site atualiza em produção

SEÇÃO 12: COMANDOS GIT - MUDAR DE BRANCH
================================================================================

Comando:
  git checkout main

Explicação:
  - "git checkout" = mudar para uma branch específica
  - "main" = nome da branch para a qual quer ir

O que faz:
  - Muda seu código de trabalho para outra branch
  - Todos os arquivos se atualizam instantaneamente
  - Você vê exatamente como o código está naquela branch

Fluxo de trabalho correto:
  1. Cria branch: git checkout -b development
  2. Faz mudanças
  3. Testa (npm run dev)
  4. Faz commit
  5. Volta para main: git checkout main
  6. Mescla: git merge development
  7. Envia: git push

Dica:
  Sempre faça git commit ANTES de mudar de branch.

================================================================================
SEÇÃO 13: COMANDOS GIT - MESCLAR BRANCHES
================================================================================

Comando:
  git merge development

Explicação:
  - "git merge" = mesclar/combinar uma branch com outra
  - "development" = branch que será trazida

O que faz:
  - Traz todas as mudanças de "development" para "main"
  - Combina os commits
  - Se não há conflitos, é automático

Passo a passo:
  1. git checkout main (vai para main)
  2. git merge development (traz development aqui)
  3. git push (envia para GitHub - VERCEL DETECTA!)

Resultado:
  Todos os commits de development aparecem em main.

DÚVIDAS FREQUENTES
================================================================================

P: Fiz uma mudança errada. Como desfaço?

R: Se NÃO fez commit ainda:
     git checkout -- app/page.js  (volta ao estado anterior)

   Se JÁ fez commit:
     git log --oneline  (encontra o commit)
     git revert abc1234 --no-edit  (desfaz)
     git push  (envia para Vercel)

P: Localhost está usando ClubeDoCinema.xlsx em vez de DEV. E agora?

R: 1. Verifique se .env.local tem:
      DROPBOX_FILE_NAME=ClubeDoCinema_DEV.xlsx

   2. Reinicie npm run dev (Ctrl+C, depois npm run dev)

   3. Verifique no terminal procurando por:
      [Dropbox] DEBUG: DROPBOX_FILE_NAME="ClubeDoCinema_DEV.xlsx"

   4. Se ainda não funcionar, procure por arquivo hardcoded:
      - Grep por 'ClubeDoCinema.xlsx' no código
      - Verifique dropboxClient.js linha 19

P: Como saber se Vercel está usando produção?

R: 1. Faça push para Vercel
   2. Vá no Vercel Dashboard
   3. Veja os Deployments
   4. Espere terminar
   5. Teste em https://clubedocinema.vercel.app
   6. Adicione um filme e veja se aparece na planilha certa

P: Posso apagar um branch depois de fazer merge?

R: Sim, seguro:
   git branch -d development  (apaga development)

P: Fiz push para main, mas descobri erro. E agora?

R: Calma, é reversível:
   git log --oneline  (encontra o commit errado)
   git revert abc1234 --no-edit  (desfaz)
   git push  (Vercel atualiza com o revert)
   Tudo volta ao normal!

P: Como ver se há conflitos antes de fazer merge?

R: git diff main development  (mostra diferenças entre branches)

P: Preciso voltar para um commit antigo?

R: Para VER como era:
     git checkout abc1234  (viaja no tempo)
     git checkout main     (volta ao presente)

   Para REVERTER (desfazer até lá):
     git revert abc1234 --no-edit
     git push
