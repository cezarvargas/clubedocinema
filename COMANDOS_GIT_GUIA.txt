================================================================================
GUIA DE COMANDOS GIT - CLUBE DO CINEMA
================================================================================
Explicação detalhada de todos os comandos git usados no projeto.

================================================================================
1. CRIAR UM BRANCH (Ramificação)
================================================================================

Comando:
  git checkout -b development

Explicação:
  - "checkout -b" = criar um novo branch (ramificação) E mudar para ele
  - "development" = nome do novo branch

O que faz:
  - Cria uma cópia do código atual em um branch separado
  - Você pode fazer mudanças SEM afetar o branch main (produção)
  - Útil para testar coisas antes de enviar para Vercel

Analogia:
  É como fazer uma fotocópia do seu trabalho para testar mudanças,
  enquanto o original fica intacto.

Exemplo prático:
  git checkout -b meu-novo-recurso
  (Agora você está em "meu-novo-recurso", isolado do main)

================================================================================
2. VER O HISTÓRICO DE COMMITS
================================================================================

Comando:
  git log --oneline

Explicação:
  - "log" = mostrar histórico de commits
  - "--oneline" = mostrar em formato compacto (uma linha por commit)

O que mostra:
  - Código do commit (exemplo: 7a13fe3)
  - Mensagem do commit (o que foi alterado)
  - Qual branch você está (HEAD -> main)

Exemplo de resultado:
  7a13fe3 Adicionar DROPBOX_FILE_NAME para usar planilha DEV
  b94c4a2 Sincronizar arquivo Ver filmes/avaliar em funcionamento
  9bf76ef Force rebuild

Usar quando:
  - Quer ver quais mudanças foram feitas
  - Quer encontrar um commit específico para reverter

================================================================================
3. GUARDAR MUDANÇAS TEMPORÁRIAS
================================================================================

Comando:
  git stash

Explicação:
  - "stash" = armazenar/guardar mudanças temporariamente

O que faz:
  - Salva todas as suas mudanças locais em um "cofre"
  - Limpa a pasta do projeto (como se você não tivesse feito nada)
  - Útil quando tem conflitos e precisa fazer outras coisas

Analogia:
  É como guardar seus documentos em uma gaveta antes de limpar a mesa.

Quando usar:
  - Mudanças locais estão conflitando com um revert/merge
  - Precisa mudar de branch mas tem alterações não commitadas

Recuperar depois:
  git stash pop  (tira do cofre e coloca de volta)

================================================================================
4. DESFAZER UM COMMIT (Revert)
================================================================================

Comando:
  git revert 7a13fe3

Explicação:
  - "revert" = desfazer/reverter um commit anterior
  - "7a13fe3" = código do commit a desfazer (vê com git log)

O que faz:
  - Cria um NOVO commit que desfaz as mudanças do commit antigo
  - O histórico fica intacto (você não apaga o commit, apenas desfaz)
  - Seguro porque não desaparece nada

Analogia:
  É como escrever um documento que diz "cancelar o commit anterior".
  A página anterior continua lá, mas foi cancelada.

Quando usar:
  - Fiz um commit errado que foi para Vercel
  - Preciso desfazer sem apagar o histórico

Obs:
  git revert --no-edit  (desfazer sem abrir editor de mensagem)

================================================================================
5. PREPARAR ARQUIVOS PARA COMMIT
================================================================================

Comando:
  git add .

Explicação:
  - "add" = adicionar/preparar arquivos para commit
  - "." = todos os arquivos modificados

O que faz:
  - Marca todos os arquivos que foram alterados
  - Prepara para serem salvos permanentemente (commit)
  - Sem git add, as mudanças não são salvas

Outras formas:
  git add arquivo.js         (adicionar um arquivo específico)
  git add app/              (adicionar uma pasta inteira)
  git add .                 (adicionar TUDO)

Fluxo correto:
  1. Editar arquivo (feito)
  2. git add . (preparar)
  3. git commit (salvar)
  4. git push (enviar)

================================================================================
6. SALVAR MUDANÇAS (Commit)
================================================================================

Comando:
  git commit -m "Descrição do que foi mudado"

Explicação:
  - "commit" = salvar permanentemente as mudanças
  - "-m" = adicionar mensagem
  - A mensagem deve descrever O QUE foi mudado

O que faz:
  - Cria um "ponto de salvação" no histórico
  - Todos os git add passam a fazer parte deste commit
  - Você pode reverter para qualquer commit depois

Exemplo bom:
  git commit -m "Adicionar detecção de WhatsApp app"

Exemplo ruim:
  git commit -m "mudou coisa"  (não explica o quê)

Estrutura da mensagem:
  - Primeira linha: resumo (até 50 caracteres)
  - Linha em branco
  - Detalhes (opcional): explique por quê foi mudado

================================================================================
7. ENVIAR PARA O GITHUB
================================================================================

Comando:
  git push

Explicação:
  - "push" = empurrar/enviar commits para GitHub

O que faz:
  - Envia seu commit local para o repositório remoto (GitHub)
  - Se estiver em "main": Vercel detecta e faz deploy automático
  - Se estiver em "development": nada acontece (não dispara Vercel)

Versão completa:
  git push origin main       (enviar branch main)
  git push origin development (enviar branch development)

Importante:
  - Só envie para main quando tiver revisado e aprovado
  - development é seguro (não afeta Vercel)

================================================================================
8. MUDAR DE BRANCH
================================================================================

Comando:
  git checkout main

Explicação:
  - "checkout" = mudar para uma branch específica
  - "main" = a branch para a qual quer ir

O que faz:
  - Muda seu código de trabalho para outra branch
  - Todos os arquivos se atualizam instantaneamente
  - Você vê exatamente como o código está naquela branch

Exemplo:
  Você está em "development" e quer ir para "main":
  git checkout main
  (Todos os arquivos mudam para refletir o main)

Verificar onde está:
  git status  (mostra qual branch você está)

================================================================================
9. MESCLAR BRANCHES (Merge)
================================================================================

Comando:
  git merge development

Explicação:
  - "merge" = mesclar/combinar uma branch com outra
  - "development" = branch que será mesclada na branch atual (main)

O que faz:
  - Traz todas as mudanças de "development" para "main"
  - Combina os commits
  - Se não houver conflitos, é automático

Fluxo correto antes de fazer merge:
  1. git checkout main       (vai para main)
  2. git merge development   (traz development para main)
  3. git push                (envia para GitHub - dispara Vercel!)

Quando há conflitos:
  - Git avisa que não consegue mesclar automaticamente
  - Você precisa resolver manualmente
  - Depois: git add . && git commit

================================================================================
FLUXO COMPLETO - DO INICIO AO FIM
================================================================================

Cenário: Você quer adicionar um novo recurso sem quebrar Vercel

Passo 1: Criar branch de desenvolvimento
  git checkout -b meu-novo-recurso

Passo 2: Fazer mudanças no código
  (editar arquivos normalmente)

Passo 3: Ver o que mudou (opcional)
  git status          (ver arquivos modificados)
  git log --oneline   (ver commits anteriores)

Passo 4: Preparar as mudanças
  git add .

Passo 5: Salvar permanentemente (commit)
  git commit -m "Descrição clara da mudança"

Passo 6: Testar no localhost
  npm run dev
  (verificar se tudo funciona)

Passo 7: Se tudo funcionou, levar para main (produção)
  git checkout main      (vai para main)
  git merge meu-novo-recurso  (traz mudanças)
  git push               (envia para GitHub - Vercel faz deploy!)

Passo 8: Se descobrir um erro depois
  git log --oneline      (encontra o commit errado)
  git revert abc1234     (desfaz aquele commit)
  git push               (envia o revert - Vercel atualiza!)

================================================================================
REGRAS IMPORTANTES
================================================================================

✅ FAÇA:
  - Sempre fazer commit com mensagens claras
  - Testar no localhost antes de fazer push para main
  - Usar development para experimentar
  - Fazer push de development sem medo (não afeta Vercel)
  - Revisar mudanças antes de fazer merge

❌ NÃO FAÇA:
  - Fazer push diretamente para main sem testar
  - Deixar mudanças não commitadas (sempre fazer commit)
  - Usar git commit com mensagem vaga ("mudou coisa")
  - Reverter commits sem avisar o time

================================================================================
DÚVIDAS COMUNS
================================================================================

P: Fiz uma mudança errada. Como desfaço?
R: Se ainda não fez commit:
   git checkout -- arquivo.js  (volta o arquivo ao estado anterior)

   Se já fez commit:
   git revert abc1234  (desfaz o commit)
   git push

P: Onde aparecem as mudanças que fiz? Localhost ou Vercel?
R: Depende:
   - Editar arquivos = só aparece no SEU computador (localhost)
   - git commit = salva no Git (ainda só no seu PC)
   - git push em development = sobe para GitHub (mas Vercel não pega)
   - git push em main = sobe para GitHub E Vercel faz deploy automático

P: Posso ver o código de development no Vercel?
R: Não. Vercel só olha para o branch main.
   Development é só para você testar localmente.

P: E se estragar development?
R: Sem problema! Delete e crie novo:
   git checkout main
   git branch -D development  (apaga branch)
   git checkout -b development (cria novo)

================================================================================
RESUMO EM UMA LINHA
================================================================================

commit = salvar mudanças localmente
push = enviar para GitHub (e Vercel se for main)
merge = combinar duas branches
revert = desfazer um commit anterior
development = branch segura para testar
main = branch de produção (vai para Vercel)
